此文记录早期设置建议，以下历史状态不代表当前仓库。当前发布信息见 [publication-status.md](publication-status.md)。

## 一、About（仓库右上角那一栏）

网页上点 **About** 旁边的齿轮，或者用命令：

```powershell
gh repo edit Aevorine/Tessera `
  --description "Multi-factor encrypted vault for Windows, with a password manager, clipboard history, notes and a file manager behind one unlock. Pairs with an Android app for LAN-only clipboard and file sync. Nothing leaves your machine."
```

**已生效，不用再跑。** 当前 20 个 topic（已到上限）：

```
desktop-app  electron  encryption  file-encryption  password-manager  privacy
python  sqlcipher  typescript  windows  android  end-to-end-encryption  kotlin
aes-256  clipboard-manager  notes-app  offline-first  windows-hello
file-transfer  golang
```

> **20 是硬上限**，超一个整批调用就 422 失败、一个都不加。`--add-topic` 是增量的，
> 所以下次想加新的必须先 `gh repo view --json repositoryTopics` 看现有多少个，
> 再决定删掉哪个——直接写一串 add 会连原有的一起丢掉（因为整批失败）。
>
> description 有 350 字符上限，上面这句约 240，还有余量。

### description 为什么这么写

一行字要回答陌生人的三个问题：**这是什么、给谁用的、有什么不一样**。

- "Multi-factor encrypted vault for Windows" —— 是什么 + 平台限制放最前面，省得
  macOS/Linux 的人点进来才发现用不了
- "with a password manager, clipboard history, notes and a file manager" —— 它不只是
  个加密工具，这几样是真正让人留下来的部分
- "behind one unlock" —— 一句话说清产品形态：一次解锁，全都能用
- "Pairs with an Android app for LAN-only clipboard and file sync" —— 跨设备是这个项目
  最容易被外人低估的部分（很多人以为"加密工具"就只能加密文件）。**"LAN-only" 这三个
  字必须在**：不写的话，"同步"两个字会让人默认有云端，而那正是这类工具最大的顾虑
- "Nothing leaves your machine." —— 加密类工具的第一顾虑就是这个，直接回答

**不要写**"个人自动化中枢"之类的抽象定位。仓库描述是给不认识你的人看的，抽象词
在这里等于没写。

### topics 的作用

GitHub 的 topic 是**搜索和推荐的主要输入**。上面十个覆盖了三类：平台
（`windows`、`desktop-app`）、功能（`encryption`、`password-manager`、
`file-encryption`、`privacy`）、技术栈（`electron`、`python`、`typescript`、
`sqlcipher`）。

### Website 一栏

留空。等有了文档站或者产品页再填——填个 GitHub 仓库自己的链接是没意义的。

## 二、Releases 页面的说明

每次发版的 notes 建议照这个模板写，重点是**让人知道该下哪个**：

**v0.1.0 的正文已经写好了，六种语言，直接贴：**
[`docs/release-notes-v0.1.0.md`](release-notes-v0.1.0.md)。

### 它为什么不写「本次改动」

v0.1.0 是**第一次公开发布**，没有上一版可以对照。"改动"这个词在这里没有参照物，
而读到它的人是第一次听说这个项目——他要知道的是"这是什么、我该下哪个"，不是一份
他从没见过的东西的差异列表。

从 v0.2.0 起再加「本次改动」一节才有意义。

### 三个产物，名字别写错

| 文件 | 适合 |
|---|---|
| `Tessera Setup.exe` | 常规安装。可选安装位置，有开始菜单快捷方式，能从「应用和功能」卸载。**卸载不会删除你的金库。** |
| `Tessera.exe` | 免安装。下载即用，可放 U 盘，不写注册表。 |
| `Tessera-v0.1.0.apk` | 安卓手机/平板端。需要手动安装，没上应用商店。 |

> **「Setup」这个词是有作用的**，不是随便起的名字：客户端的更新逻辑靠文件名里有
> 没有它来区分安装版和免安装版（见 `updateService.ts` 的 `selectUpdateAsset`）。
> 改名会让所有已安装客户端挑不出该下哪个，而且不报错——只是永远提示不出更新。

## 三、Packages —— 这个页面用不上

你给的那个链接现在是空的，**而且应该一直是空的**。

GitHub Packages 是发布 npm / Docker / NuGet / Maven 这类**软件包**的地方，供别的项目
作为依赖引用。桌面应用的分发渠道是 **Releases**，两者不是一回事。

除非将来把 `core/` 拆成一个真正给别人 `pip install` 的库，否则这个页面不需要动。

## 四、还没做但值得做的

按性价比排：

1. **一张截图放进 README 顶部。** 加密工具最大的信任障碍是"看不见它长什么样"。
   一张主界面截图的说服力超过前三段文字。
2. **`SECURITY.md`** —— 说明漏洞报告发到哪里。GitHub 会在仓库的 Security 标签页
   自动展示它。对一个加密工具来说，没有这个文件本身就是个信号。
3. **仓库 Social preview 图**（Settings → General → Social preview）。决定了链接
   分享到别处时显示什么，默认是一个没有信息量的灰色方块。
4. **应用内的「关于」页面** —— 现在版本号只出现在设置页的更新区。一个正经的关于
   页应当有：版本号、许可证、项目主页链接、第三方组件清单。最后一条不只是礼节，
   `LICENSE` 里承诺了第三方组件保留各自许可证，那就该有个地方能看到它们。
