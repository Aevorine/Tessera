# 架构说明

## 设计目标

轻量、模块可插拔、不过度设计。新增应用场景不应要求改动 `core/` 或其他模块。

## 分层

- **`core/`** — 跨模块公共基础设施，只包含真正被 ≥2 个模块共用的东西：
  - `config.py`：环境变量（`IDEAL1_` 前缀）+ 可选 `config.toml`。
  - `logging.py`：`get_logger(name)`，统一格式，避免各模块各写各的 `print`。
  - `registry.py`：基于 `pkgutil.iter_modules` 的模块发现，`ModuleInfo` dataclass。
- **`modules/`** — 每个子文件夹一个独立场景，通过 `MODULE_META` 字典 + 可选 `register()`/`run()` 接入。规范权威文档在 `modules/README.md`。
- **`scripts/run.py`** — 唯一的命令行入口，`list` 列出模块、`run <name>` 调用模块的 `run()`。

## 为什么不用更重的方案

- 不引入插件基类/生命周期钩子：目前只有一个模板模块，真正出现 2-3 个模块后再看是否需要更多共享行为，届时再抽象。
- 不引入 YAML/新依赖做模块元信息：纯 Python dict 已经够用，且对使用者最直观。
- 不用 `src/` 布局：项目就地运行（`python scripts/run.py ...`），不打包发布。

## 何时该改这份文档

新增/删除顶层目录、改变模块发现规则时，同步更新这份文档、`CLAUDE.md`、`modules/README.md`，避免文档与代码脱节。
