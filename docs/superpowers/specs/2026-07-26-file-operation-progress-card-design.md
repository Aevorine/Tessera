# 文件快捷键实时任务卡设计

**状态：用户已确认，待审阅**
**日期：2026-07-26**

## 目标

当用户在资源管理器触发 `Ctrl+V`、`Delete` 或 `Shift+Delete` 时，显示一个不抢焦点的右下角实时任务卡。任务卡展示当前操作、当前文件、已完成/总量、速度、已用时间、预计剩余时间、取消入口和完成/失败结果。用户可在 File Vault 设置中选择任务卡位置、自动隐藏时间与紧凑模式。

此设计保持现有高速 Win32 文件引擎、冲突策略、回收站语义和永久删除确认不变；只为其补充可靠的进度报告和界面呈现。

## 已确认的交互

- 默认位置为右下角；设置提供九宫格：左上、上中、右上、左中、居中、右中、左下、下中、右下。
- 每次有效的全局粘贴/删除操作自动显示任务卡，无需打开 File Vault 主窗口。
- 任务卡为非激活悬浮窗：不会夺取资源管理器焦点、不会打断键盘输入。
- 设置提供自动隐藏时长：3、5、10 秒；仅在成功完成后倒计时。失败、取消和永久删除的异常状态保持显示，直到用户关闭。
- 设置提供紧凑模式。紧凑模式只显示操作名、百分比、速度、已用/剩余时间；展开模式额外显示当前路径、文件数/总大小和取消按钮。
- `Shift+Delete` 仍先显示现有永久删除确认；只有用户确认后才创建任务卡。

## 界面状态

### 准备/扫描

显示不确定进度条和“正在扫描项目…”。现有传输引擎是边枚举目录边复制的流式设计，因此目录树尚未枚举完成时不显示伪造百分比或 ETA；枚举结束、总量冻结后才切换到确定进度。实现不得为了显示百分比做第二次磁盘扫描。

### 运行中

| 操作 | 主进度 | 次要信息 |
| --- | --- | --- |
| Ctrl+V 复制/跨盘剪切 | 已复制字节 / 总字节，缺少字节时使用文件数 | 当前路径、文件数、MB/s、已用时间、ETA |
| 同盘 Ctrl+X 粘贴 | 已快速移动条目 / 总条目 | 当前路径、已用时间；不展示无意义的 MB/s |
| Delete | 已删除条目 / 总条目 | 当前路径、项目/秒、已用时间、ETA、已释放空间（可获得时） |
| Shift+Delete | 已永久删除条目 / 总条目 | 与 Delete 相同，使用危险色和“不可恢复”标识 |

速度使用近 2 秒窗口的平滑移动平均，ETA 仅在已处理至少 1 秒且总量已知时显示。进度事件最多每 200 ms 刷新一次，避免对大文件和海量小文件造成可测性能损失。若当前 Windows 回收站 API 没有逐项回调，界面必须明确显示“系统正在移至回收站”、已用时间和不确定进度，禁用取消与 ETA；为满足逐项进度目标，正式实现改用支持 `IFileOperationProgressSink` 回调的 Shell `IFileOperation` 回收站路径，并在 API 不可用时采用该诚实降级。`IFileOperation` 不提供 `Abort()`；回收站卡片始终禁用取消，并在结束后以 `GetAnyOperationsAborted()` 和逐项回调报告观察到的真实结果，未开始项目保留原样，且不把已移入回收站的项目误报为已恢复。

### 结束

- 成功：显示完成数量、总大小、平均速度和总耗时；按所选时长自动收起。
- 部分失败：显示成功/失败数量、首个失败原因，并提供“查看详情”。
- 取消：显示安全取消结果和已处理数量；不可逆删除不承诺恢复已完成的部分。
- 快速任务：若在 300 ms 内成功完成，不创建任务卡，避免初始化 UI 造成闪烁和额外开销。

## 架构与数据流

```text
Explorer shortcut
  -> hook_agent.exe
  -> hook_cli.py
  -> core.fileops.progress_ui.gui_paste/gui_delete
  -> core.fileops.engine.transfer/delete_items
       -> thread-safe TaskProgress snapshots
  -> non-activating native Task Card (Tk + Win32 styles)
```

现有 `TransferReport` 和 `_Progress` 已提供部分字节/文件计数，`progress_ui.py` 已有后台 worker 与延迟显示机制。本实现将把它们扩展为不可变快照，不另起轮询文件或重新扫描文件树。

### 进度模型

新增内部 `TaskProgress` 快照，包含：

- `operation`、`phase`（scanning/running/completed/failed/cancelled）
- `current_path`、`files_done`、`files_total`、`bytes_done`、`bytes_total`
- `started_at`、`elapsed_seconds`、`speed_bytes_per_second`、`eta_seconds`
- `items_done`、`items_total`（独立计入同盘快速移动的顶层条目）
- `errors_count`、最多 6 条 `{path, message}` 错误摘要、`cancel_requested`、`recycle`

所有扫描、复制、快速移动、删除和错误写入经同一把进度锁更新；UI 线程只读取一次复制后的快照，绝不持锁做界面或磁盘工作。每次成功 `MoveFileExW` 快速移动后更新独立的 `items_done`，确保同盘 Ctrl+X 粘贴不会显示 0/0。进度回调限频至 200 ms，最终状态无条件发送。

### 任务卡窗口

保留现有 `progress_ui.py` 的惰性导入和快速任务路径，避免给原本毫秒级的复制/删除增加 Tk 初始化成本。超过延迟阈值的任务创建一张原生卡片。若卡片初始化、绘制或关闭失败，捕获错误并记录日志，文件 worker 必须继续；worker 改为非 daemon，调用方在返回前等待其结束，避免 UI 故障导致 pythonw 退出并中止文件操作。

卡片先以 Tk `withdraw()` 创建但不映射；取得 HWND 后先设置 Win32 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` 和 `WM_MOUSEACTIVATE -> MA_NOACTIVATE`，再通过 `SetWindowPos(..., SWP_NOACTIVATE | SWP_SHOWWINDOW)` 完成首次显示，绝不使用 Tk 的默认首次 `deiconify()` 路径。这样取消/关闭按钮仍可点击，而资源管理器始终保持前台。验收必须记录操作前后前台 HWND 相同。位置按鼠标所在显示器的工作区计算九宫格坐标，留出固定边距，避免遮住任务栏。多显示器时，卡片显示在触发快捷键时鼠标所在的屏幕。

全局代理可并发启动多个 `hook_cli` 进程。每张运行中的卡片通过命名互斥量分配 0–3 号槽位，在所选九宫格位置沿内侧垂直堆叠；槽位用完时新任务仍执行，但仅写入日志并不创建第 5 张卡，避免遮挡和阻塞文件操作。卡片结束后立即释放槽位。

### 设置存储

新建 `%LOCALAPPDATA%\Ideal1 File Vault\FileHook\progress_preferences.json`，由 File Vault 后端原子写入，运行时 `hook_cli.py`/`progress_ui.py` 只读。这一位置不依赖便携 EXE 的目录，因此开机启动的稳定运行时也能读取相同偏好。

默认值：

```json
{
  "position": "bottom-right",
  "auto_hide_seconds": 5,
  "compact": false
}
```

设置页新增“文件操作任务卡”区：九宫格选择器、自动隐藏下拉框、紧凑模式开关和静态预览。保存后下一项任务立即使用新设置；不会中断正在进行的任务。

## API 边界

- 后端新增读取/保存任务卡偏好的 RPC，使用现有 `vaultApi` 模式和严格枚举校验。
- 前端新增任务卡偏好类型与设置组件；不让渲染层直接读写文件。
- 全局快捷键路径保持独立于 Electron 后端连接：任务卡必须在主应用关闭、仅开机自启动代理运行时仍可显示。
- 应用内文件管理器现有 RPC 进度继续使用后台 NDJSON 事件；可复用 `TaskProgress` 的格式化逻辑，但不依赖全局悬浮卡。

## 错误与安全

- 无效/损坏的偏好文件回退到默认右下角、5 秒、非紧凑模式，并记录诊断，不阻断文件操作。
- 任务卡创建失败时，文件操作继续执行；错误写入日志，不让 UI 故障影响复制或删除。
- 永久删除确认失败、用户取消、权限错误、文件占用、磁盘空间不足均在结束状态明确显示。
- 复制、跨盘移动和永久删除的“取消”只设置已有 Win32 取消旗标；不强制终止线程，也不误报已完成项目为可恢复。回收站 `IFileOperation` 路径不提供取消按钮：它没有公开的 `Abort()`，最终结果严格按进度回调和 `GetAnyOperationsAborted()` 记录已完成与未开始项目。

## 验收与测试

1. Ctrl+V 大文件：验证字节、速度、已用时间和 ETA 持续更新，且复制结果可正常打开。
2. Ctrl+V 海量小文件：验证扫描态后转为文件数量进度，界面刷新不降低引擎性能。
3. Delete 与 Shift+Delete：验证各自的回收站/永久删除语义、风险文案和实时项目数。
4. 九个位置、三档自动隐藏、紧凑模式均持久化，重启应用和仅代理启动后仍生效。
5. 启动资源管理器操作时，任务卡不激活、不改变前台窗口，也不截获额外键盘输入。
6. 单元测试覆盖偏好校验、坐标计算、ETA/速度计算、进度限频和损坏配置回退；进行真实 Windows 手工验收。

## 非目标

- 本阶段不建立跨任务排队系统或长久历史中心。
- 不改变 Ctrl+C/Ctrl+X 的剪贴板语义。
- 不在任务卡中加入文件内容预览或联网功能。
